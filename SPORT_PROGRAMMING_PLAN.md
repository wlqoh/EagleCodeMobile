# План: переход с «классического спорта» на спортивное программирование

> Самодостаточный план для репозитория `EagleCodeMobile` (Expo SDK 57, Expo Router, TanStack Query).
> Выполняется без доступа к истории обсуждения: все решения и данные — ниже.

## 0. Цель

Сейчас приложение EagleCode Sport наполнено дисциплинами классического спорта (лёгкая атлетика, бег, борьба,
плавание, бокс, трейлраннинг): в демо-данных, заглушках, экранах рейтинга, соревнований, результатов и профиля.
Нужно оставить **только спортивное программирование**: пять официальных дисциплин ФСП, соответствующие
соревнования, форматы результатов, разряды и регалии участников.

## 1. Принятые решения (итог интервью)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Где меняем | **Только мобильное приложение** (`EagleCodeMobile`). Веб (`../EagleCode/src`) и Django (`../EagleCode/backend`) не трогаем. Контракт API (`src/core/types.ts`, `DataClient`, `HttpDataClient`) **не меняется**. |
| 2 | Список дисциплин | **5 официальных дисциплин ФСП** (см. §3.1). |
| 3 | Хранение дисциплин | Справочник `src/core/disciplines.ts`; в типах поле остаётся `string`. Профиль — мультивыбор чипами, рейтинг — чипы из справочника. |
| 4 | Названия | В данных — **полное официальное название**; в чипах и бейджах — **короткое**; полное — в деталях соревнования и в редактировании профиля. Хелпер с фолбэком на исходную строку. |
| 5 | Спортивный разряд | Остаётся `sportTitle: string`, но выбирается из **закрытого списка** `src/core/ranks.ts`. |
| 6 | Регалии | Регалии = **чип разряда/звания** (`sportTitle`) + чипы **`verified`-достижений категории «Награды»** (`getAchievements(athleteId)`). |
| 7 | Цвета регалий | **Медальная шкала**: новые тона `Badge` — `bronze` (III–I разряд), `silver` (КМС), `gold` (МС), `elite` (МСМК/ЗМС); юношеские — `default`; награды — `primary`. Токены для обеих тем. |
| 8 | Где показывать регалии | **Оба профиля** (вкладка «Профиль» и `athlete/[id]`): ряд чипов под именем через общий компонент `RegaliaChips`. Подзаголовок = только организация. Дисциплины — единый нейтральный стиль в обоих профилях. |
| 9 | Формат (команды/онлайн) | Контракт `Competition` **не меняем**. Командность и онлайн описываются текстом в `description`/`schedule`/`location`. Заявка остаётся индивидуальной. |
| 10 | Дисциплина в соревнованиях | Бейдж (короткое название, тон `default`) на `CompetitionCard`, полное название в фактах карточки соревнования, **второй ряд чипов-фильтров по дисциплине**. |
| 11 | Требования к участию | Общая часть + требования по дисциплине из справочника (поле `requirements`). «Медицинский допуск» убрать. |
| 12 | Формат результата | `score` зависит от дисциплины (см. §3.4). Плашка «Лучший темп» → «Решено задач». |
| 13 | Метры и уровни Орла | **Не меняем** (брендовая метафора высоты). |
| 14 | Демо-данные | Замена контента с сохранением id + **5 соревнований (по одному на дисциплину, добавить `cp5`)**; разные разряды и награды у спортсменов, чтобы была видна вся шкала. |
| 15 | Сохранённая mock-база | Ключ `eaglecode.mock.v1` → **`eaglecode.mock.v2`**, при первом старте **удалять `v1`**. |
| 16 | Иконки дисциплин | **Не добавляем**, везде остаётся `Trophy`. |

### Вне объёма (сознательно)

- Веб-фронтенд и бэкенд (включая `seed_demo.py` и модель `Discipline`). В api-режиме сервер будет отдавать старые
  «спортивные» дисциплины — UI отобразит их как есть благодаря фолбэкам (см. §6).
- Сущность «Команда», командные заявки, поля `format`/`mode`/`teamSize`.
- Переименование «метров», уровней Орла, идентификаторов кода (`Athlete`, `athleteId` и т.п.).
- Иконки по дисциплинам.
- Пересчёт заглушек из данных (`placeholders.ts` остаются статичными, меняются только тексты).

> **Осознанное отступление от CLAUDE.md**: `seed.ts` и `placeholders.ts` помечены как перенесённые из веба 1:1;
> после этой задачи они расходятся с `../EagleCode/src/services/seed.ts` и `../EagleCode/src/pages/user/*`.
> Обновите комментарии-заголовки этих файлов (см. §4.1, §4.2), чтобы расхождение было явным.

### 3.3 Правило регалий

Ряд регалий = `[чип разряда] + [чипы наград]`:

- Чип разряда: `sportTitle` с тоном `rankTone(sportTitle)`. **Не показывается**, если `sportTitle` пуст или равен `NO_RANK`.
- Чипы наград: `awardRegalia(achievements)` → `Badge tone="primary"` с `title`.
- Если регалий нет совсем — ряд не рендерится.

### 3.4 Формат результата (`CompetitionResult.score`, строка)

| Дисциплина | Формат | Пример |
|---|---|---|
| Алгоритмическое | `N задач · штраф` (ICPC) | `9 задач · 1142` |
| Продуктовое, БАС, Робототехника | баллы жюри/судей | `87.5 б` |
| Инфобез (CTF) | очки | `4 350 pts` |

Кода это не требует (поле строковое), это соглашение для сида и для админов. Проверить вёрстку строки результата
в `results.tsx` и в блоке последних результатов `profile.tsx` на ширине 360 pt: бейдж `score` не должен выталкивать
метры за край (у `resultInfo` уже `flex: 1`; при переполнении добавить `numberOfLines={2}` к названию соревнования).

## 6. Поведение в api-режиме (`EXPO_PUBLIC_DATA_SOURCE=api`)

Бэкенд не меняется, поэтому:
- С сервера могут прийти старые дисциплины («Лёгкая атлетика») → `disciplineLabel` покажет исходную строку;
  в фильтрах рейтинга/соревнований их не будет (чипы из справочника) — такие записи видны только в «Все».
- Неизвестный `sportTitle` → чип тона `default`; в редактировании профиля он добавляется как отдельный вариант.
- `GET /athletes/{id}/achievements` для **чужого** спортсмена может вернуть 403 → `RegaliaChips` показывает только разряд.
- Требования соревнования для неизвестной дисциплины = только общая часть.

Ни один из этих случаев не должен давать падения или пустого экрана ошибки.
